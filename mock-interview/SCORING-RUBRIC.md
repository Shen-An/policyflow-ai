# 评分细则与复盘模板

## 一、五维评分（总分 100）

### A. 概念与架构认知（15 分）
| 分档 | 表现 |
|---|---|
| 13–15 | 每个概念都能立刻对接到自己项目里的具体实现，主动给出取舍 |
| 9–12 | 概念准确，但只是标准答案，缺少工程映射 |
| 5–8 | 概念大体对，细节含糊（如说不清 ReAct 与 CoT 的执行差异） |
| 0–4 | 概念混淆或明显错误 |

### B. 设计与决策能力（25 分）
| 分档 | 表现 |
|---|---|
| 21–25 | 每个方案都能说"为什么选 A 不选 B"+"A 在什么边界失效"，主动列候选方案 |
| 15–20 | 能说清选型理由，但边界条件要追问才想得到 |
| 8–14 | 只会描述现有方案，追问 tradeoff 就卡住 |
| 0–7 | 只会复述框架文档 |

### C. 落地与工程化（30 分）—— SP/SSP 分水岭
| 分档 | 表现 |
|---|---|
| 25–30 | 有真实故障复盘；容错/成本/可观测性三件套齐全；能报出线上数字 |
| 18–24 | 想过异常处理和评测，但没上过真实流量 |
| 10–17 | 只有 try/except 级别的容错，无评测无监控 |
| 0–9 | 纯 Demo，被问到"线上怎么办"完全空白 |

### D. 代码基本功（15 分）
| 分档 | 表现 |
|---|---|
| 13–15 | 一次写对，主动说复杂度和边界，能改写成 Agent 场景变体 |
| 9–12 | 写对但需要提示边界条件 |
| 5–8 | 思路对，代码有明显 bug |
| 0–4 | 写不出来 |

### E. 行业视野与自省（15 分）
| 分档 | 表现 |
|---|---|
| 13–15 | 知道近一两个月的关键变化并有自己判断；能主动、准确地说出自己项目的不足 |
| 9–12 | 知道热点名词，判断偏浅 |
| 5–8 | 只知道半年前的东西 |
| 0–4 | 说不出项目不足（视为无自省能力，直接压分） |

### 信号修正
- 强信号每条 +1（上限 +8）
- 弱信号每条 −1（下限 −8）

## 二、等级线

| 总分 | 结论 |
|---|---|
| ≥85 | **SSP** —— 有生产级 Agent 主导经验，可独立负责模块 |
| 70–84 | **SP** —— 工程化思维成型，需带教 |
| 55–69 | **普通 Offer** —— 概念清楚，落地偏 Demo |
| <55 | **不通过** —— 停留在调 API / 背概念阶段 |

## 四、给自己（候选人）的使用建议

- 每场只挑 **一个项目** 让陈昱深挖，追问链会打到 L5–L6，比广度轮更有收益。
- 回答里强制自己带 **三个数字**：一个规模数字、一个质量数字、一个成本/延迟数字。
- 被问倒时不要硬编，说"这块我没做过，但我会这样排查……"比编造扣分少。
- 每场复盘存入 `sessions/YYYY-MM-DD-<轮次>.md`，两周后重考同一批扣分点。
