# 自我介绍稿

> 用途：面试开场自我介绍，背诵用。三版：1 分钟 / 2 分钟（默认）/ 3 分钟。
> 写法原则：先大白话讲清「项目干什么的」，再进技术点；每个技术点用「问题句」开头。
> **术语一个都不删**——简历是锚，对方照着简历问。要做的不是回避词，是让每个词出现时就自带落点（我拿它干了什么、边界在哪）。

## 主版本（约 3 分钟）

面试官好，我叫 XX。我本科在长安大学读软件工程，专业排名第 7，保研到本校计算机科学与技术，现在研一结束。科研上我以第一作者发表了一篇 IEEE SMC，已录用，另有一篇一作的 AAAI 在审。工程上我近一年主要做大模型应用方向，重点介绍我独立完成的一个项目——PolicyFlow AI。

**先说这个项目是干什么的。** 公司员工经常要问「报销上限是多少」「请假走什么流程」这类制度问题，自己翻文件很费劲，问行政又要等。我做的就是一个企业政策问答助手：把公司的政策文件导入系统，员工像聊天一样提问，它从文件里找出依据、给出带引用的回答。制度问题答错是有后果的，所以它的底线是：找不到依据就明确说「查不到」，绝不编造。前后端和整个 AI 链路都是我一个人开发的。

在这个项目里我重点解决了三个问题。

**第一个问题：怎么证明它答得准，而不是我自己觉得准。** 我建了一套评测体系：用公开的中文检索基准做金标准，专门混入两百篇无关文档来防止指标虚高，用 Hit@1、MRR 这类业界通用指标来量化「正确文档有没有被排到前面」。而且线上问答和离线评测走同一条链路，评出来的数字就是用户真实体验到的效果。检索本身是双路混合再加重排，每个策略都能开关对照，效果差多少数据说话。

**第二个问题：多轮对话怎么不丢上下文。** 比如用户先问了差旅报销，接着只说一句「给我个模板」，系统得知道他要的是差旅报销模板。我做了分层的记忆设计——从原始消息、近期摘要到长期的用户偏好，按相关性和重要性排序召回；追问的短句会先结合历史改写成完整问题再去检索。同时有一条硬规则：记忆只是参考，不能覆盖当轮从文件里查到的证据。

**第三个问题：出错的时候怎么兜底。** 大模型应用最怕失控，我给每轮请求设了预算——调用次数、耗时超了就收口给出降级回答；检索跑偏会自动重检一次；回答发出前还要过一道质量门，不合格就改写或拒答。宁可说「查不到」，也不输出编造的制度条款。

在这之前我还做过一个电商客服 AI 助手，Java 技术栈，帮商家自动处理投诉、退款这类工单。印象最深的是给退款、建单这种操作加了幂等保护——防止系统超时重试导致给用户重复退两次款，这是真金白银的问题。

日常我用 Claude、Codex 这些 AI 工具辅助开发，但关键设计都是自己想清楚边界，什么是真实现、什么是简化实现，我在文档里都写得明明白白。希望能加入贵团队，谢谢。

## 1 分钟口语版（默认开场用这个；结构 = 标准模板：身份岗位 → 经历1量化 → 经历2 → 能力对JD → 方向+公司 → 引导追问）

> 念一遍约 60 秒。口语措辞，术语留给追问。
> 每次面试前填：姓名、岗位名、JD 关键词（照抄对方 JD 原词）、公司吸引点（一句具体的）。

面试官您好，我叫【姓名】，长安大学计算机专业的研一学生，本科是软件工程，年级前 7 保研的，应聘咱们这边的【大模型应用开发实习生】。

在校期间我独立做了一个企业政策问答助手，就是员工问报销、请假这类制度问题，它去公司文件里找依据回答，带出处，查不到就直说，不瞎编。我负责整个前后端和 AI 链路，还搭了一套检索评测，接了重排之后 Hit@1 从 78% 提到了 86.7%，MRR 从 0.88 提到 0.93。之前还做过一个电商客服 AI 助手，通过意图识别自动分流投诉、退款这些工单，拿不准的自动转人工，让商家的客诉基本能闭环处理不用人盯着。

我比较擅长的是 RAG 检索和评测、多轮对话的记忆设计，还有 AI 应用的兜底，跟咱们 JD 里提到的【RAG / Agent / 大模型应用】挺匹配的。我想在大模型应用这个方向长期做下去，贵司的【业务/产品，写一句具体的】我也很感兴趣。接下来您更关注哪一块，我可以展开讲，比如检索评测或者记忆设计。

> 变体：面算法/研究岗时，把电商那句换成「另外我一作发了篇 IEEE 会议论文已录用，还有一篇 AAAI 在投」，电商项目留给追问。
>
> ⚠️ **电商客服那个项目是在开源项目基础上 fork 二开的。** 被问「这是你自己做的吗」不能含糊，也不能只说「拿过来改了一下」（等于交白卷还自曝）：
> 「底子是一个开源项目，我 fork 之后重做了 ____——所以准确说法是**二开，不是原创，这两个词我不混**。」后面立刻接一个**具体改动**：现象 → 怎么定位 → 怎么改 → 怎么验证。〔待补：改动清单，见 wiki 待办〕
> 用词红线：不说「参与过 / 接触过 / 落地过」，负责哪一格就说哪一格。

## 2 分钟版（默认主用这版：开源背书 + 三个问题 + 简历词就地安放）

> 正常语速 2 分 15 秒左右。超时先砍：语音项目整段 → LangGraph 段换成一句版（见「一句版兜底」）。
> 结构：**钩子 → 它是干什么的 + 物证 → 「我简历上那串词，我按三个问题讲，每个词落在它自己的位置上」→ 三个问题 → 第二个项目 → 收口递演示**。
>
> ⚠️ **词不能删。** 简历是锚，面试官一定照着简历问。开场把词摘掉，他照样会问，而且你等于主动把「简历上写了、嘴里不说，是心虚还是藏了」这个怀疑送出去。
> 正确动作是**给每个词一个落点**：让它出现在自我介绍里的那一刻，就自带「我拿它干了什么、边界在哪」。

面试官您好，我叫【姓名】，长安大学计算机专业硕士在读，本科软件工程、年级前七保研的，应聘咱们的【大模型应用开发实习生】。

〔钩子句，从下面六条里挑一条，别每次都同一条〕

先说我在做一个什么东西。企业里员工老要问「报销上限是多少」「请假走什么流程」，自己翻文件很费劲，问行政又要等。我做的是：把制度文件导进去，员工像聊天一样提问，它去文件里找依据、给出带引用的回答。制度问题答错是有后果的，所以它的底线是——查不到就直说查不到，绝不编条款。这个项目从七月做到现在，两个多月、将近四百个 commit，开源在 GitHub 上，不是 fork 别人的，前端、后端、整条 AI 链路我一个人做的。

我简历上写了一串词——RAG、Multi-Agent、LangGraph、MCP、Vue——**我不当清单念，我按我遇到的三个问题讲，每个词落在它自己的位置上。**

**第一个问题：它答得准不准，不能我说了算。** 这块就是 RAG：BM25 加 LightRAG 双路召回、RRF 融合，外面再挂一层重排开关。然后我专门搭了评测——公开中文检索基准做金标、混进两百多篇无关文档防指标虚高，同一份用例只切「重排开不开」这一个变量，Hit@1 从 78% 到 86.7%，MRR 从 0.88 到 0.93。口径您要追，我展开讲。

**第二个问题：多轮别丢上下文。** 用户先问差旅报销，再甩一句「给我个模板」，系统得知道他要的是差旅报销模板。我做了四层记忆加查询改写，从原始消息、近期摘要到长期偏好按相关性和重要性召回；再加一条硬规则：记忆只是参考，不能盖掉这一轮从文件里查到的证据。

**第三个问题：Agent 不能失控。** 这块就是 Multi-Agent 编排——我做的是**中心化那一型**：Orchestrator 串分诊、检索、回答、评审四个角色，共享一份轮内状态；**没做成自由群聊是我主动选的**，制度问答这种场景里群聊不可控。外面套预算：工具 8 次、模型 16 次、整轮 180 秒，超了就收口；答案发出去前还要过一道 PASS / REVISE / REFUSE 的门。工具接入我是按 **MCP** 协议做的，stdio 和 HTTP 两种传输的客户端自己写的，企业连接器那层是 mock 标注的——**这句我主动说，不想把 mock 讲成对接过飞书。**

编排这块，我一开始是照 **LangGraph** 的 state、节点、边那套思路设计的，后来发现我的场景要的是「每一步都能被预算和门控卡住」，所以自己手写了一版。**正因为手写了一遍，框架替我省的那层——检查点、状态回放——我很清楚它值多少钱。**

另外我还从 0 做了一个语音模拟面试系统，题库是五月起每天自动爬下来的上千道面经。里面踩过一个致命 bug：面试官模型会把答案自己说出口。我为这一件事做了三层拦截，最后又加了一层根治——把「出题」和「评判」拆成两个角色。

技术栈 Python 为主，Java、Spring Boot 加前端都能独立做；**前端这版是 React + AntD，Vue 3 我在另一个工具项目里写过**，两边都能上手。我不是什么都会，但**我简历上写的每个词，都能讲到代码那一层**。您更关注哪一块，我可以展开讲，或者直接打开仓库指给您看。

> 「JD 里写『AI 智能应用场景识别和提取、Agent 系统规划、功能测试』，我按这三块对：
> **场景识别**——我做一个入口分诊，判据不是让模型说这题难不难，是判它要不要外部数据、要走几步、有没有岔路；

### star 数怎么说才不像炫

「star 数不大，我不拿它说事。**我要讲的是代码全在公开仓库，您现在就能翻，也可以现场跑给您看。**」

> ⚠️ 52 这个数字当场一搜就有，说「五十多个」别说整数；每次面试前重新核（`api.github.com/repos/Shen-An/policyflow-ai`）。
> 拿 star 当卖点会被「哪来的星」追穿；**当物证用**（非 fork、提交历史完整、可现场演示）才是它的价值。

### 形容词红线（词留着，形容词去掉）

- 「**生产级 / 企业级 / 高可用**」一律换成机制名词：预算收口、发布门、开关对照、mock 标注。
- 「精通」不用；简历写「熟练 / 掌握」的地方，口播说「我做过 ____，做到 ____ 这个程度」。
- 只有两处主动降调，而且是加分：**数字口径**（N、没做显著性检验）和**并发**（单机 demo）。

## 三版切换

- 「简单介绍一下自己」→ 2 分钟版（默认）；对方明显赶时间 → 1 分钟口语版
- 「详细讲讲你的项目」→ 3 分钟版的「项目干什么的」段 + 三个问题段（念的时候口语化，别背书面句）
- 三版共用一条原则：**词当场说、当场定性；实验设置和数字口径留到追问再展开。**
- **钩子只换 2 分钟版的第一句**，后面骨架别动。连续面好几家还共用同一条钩子，容易被同集团的人对出来——每场换一条。
- 开口前的自贬词清零：**「看过 / 了解 / 稍微 / 只能说 / 啥的」一个都不许出现**，自己实现过的东西说「做过」，说到具体程度为止。
- 缺口怎么说不不道歉、不关门：话术库在面试 wiki `topics/hr-honest-reframing.md`（生产经验 / 课程学的技术 / 手调参数 / fork 项目 / 被指缺陷 五组）。

## 留给追问环节的术语（介绍里故意不展开）

- 双路混合 = LightRAG + BM25，RRF 融合；重排 = 默认本地 lexical fusion，可选 NVIDIA cross-encoder（opt-in，失败 503 不静默回退）→ 说「**开关对照**」，不说「默认在线」。
- 分层记忆 = 四层：L0 原始消息 / L1 近窗+滚动摘要 / L2 事件向量摘要 / L3 实体，排序公式 relevance × (importance + recency)。
- 兜底 = Turn Budget 限流收口、跑题重检一次、PASS/REVISE/REFUSE 发布门、工具幂等键。
- 「Multi-Agent」**要说，但一开口就定性**：中心化 Supervisor 流水线 + tool-using 主 agent，检索是服务，不是群聊框架；**群聊是主动放弃的**（docs/08 口径）。
- 「LangGraph」口径同 `RESUME-SKILLS.md`：**落地以自研中心化编排为主**；被追就讲 state / 节点 / 边怎么管，以及为什么预算和门控这层我必须自己写。
- 「MCP」被追「你接了什么 server」：自建 stdio demo server + mock 企业连接器（飞书 / Confluence 是 mock 标注），**别顺口说成对接过真实企业系统**。
- 指标被追问实验设置时（口径与简历逐项对齐，不多说简历没写的）：「基于公开中文基准 CRUD-RAG 做开关对照，检索是 Hybrid 双路——LightRAG 加 BM25、RRF 融合，对照的开关就是 NVIDIA cross-encoder 重排；线上问答和离线评测走同一条链路，所以指标可复现。」
- 两项目兜底叙事分工：电商讲**业务后果**（幂等防重复退款、转人工），PolicyFlow 讲**检索质量**（跑题重检、质量门）；被问「怎么都有兜底」→ 演进故事：电商先踩坑做第一版，PolicyFlow 沉淀成通用机制。
