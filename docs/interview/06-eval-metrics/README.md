# 06. 评估：Hit@K / MRR / CRUD

## 一句话

主指标 **Hit@1 / Hit@5 / Hit@10 / MRR**，必须写清 **检索策略 + N**；  
金标走 CRUD `questanswer_*`，语料只进 **`eval_test` 测试库**。

## 为什么评测是简历核心

- 能证明「不是 demo 话术」，而是可重复实验  
- Chat 与 Eval **同编排/同检索语义**，避免两套逻辑  
- 强制你说清采样、干扰文档、策略名，防止虚高

## 指标怎么讲

| 指标        | 含义（口述）                   |
| --------- | ------------------------ |
| **Hit@K** | 金标文档是否出现在前 K             |
| **MRR**   | 第一个正确文档排名的倒数平均           |
| **策略**    | Hybrid / BM25 / …（写在结果上） |
| **N**     | 用例数（优先随机 50/100，勿无脑全选）   |

示例表述：

> Hybrid，N=50，Hit@5=…，MRR=…；同设置下 BM25 为 …。在 1-doc 匹配任务上两者接近，我不宣称 Hybrid 显著更优。

## 白话详解（指标 + 金标 + 测试库）

### 两个指标是啥（打比方）

- **Hit@K**:正确资料有没有出现在你翻的**前 K 条**里。*例:Hit@5=0.8,意思是 80% 的题,正确资料进了前 5 条。像考试找参考答案,正确那本在你翻的前 5 本里就算命中。*
- **MRR**:正确资料**排得多靠前**的平均分。排第 1 得 1 分、第 2 得 0.5 分、第 3 得 0.33 分…越靠前越高,所有题平均一下。*比 Hit@K 更细,能看出「排第 1 还是排第 5」。*

为什么这俩是主指标?因为对企业问答来说,**正确的制度条款排得越靠前,用户越快拿到对的答案**——比「召回率」这种笼统数更贴场景。

### 金标 / 干扰文档 / 隔离测试库

- **金标(gold)**:人工标好的「标准答案 / 正确资料」,用来给系统打分。*没金标就没法判卷。*
- **干扰文档(distractor)**:故意混进去的**无关文档**,让测试更难、更接近真实。*例:库里只有 1 篇年假制度、你问年假,瞎找都 100% 命中——这种分数虚高。放进 200 篇无关的,还能找到那 1 篇才算真本事。*
- **隔离测试库**:测试数据**只灌进专门的「测试库」**(`eval_test`),**绝不灌进 HR / 财务业务库**。*两个原因:一是怕测试数据污染线上;二是怕「在业务库里放一篇金标、查那篇、100% 命中」这种自欺欺人的虚高。*

### 两套金标,各进各的库

1. **CRUD 金标**(量化主指标用):一个公开的中文问答数据集,取它的 `questanswer` 部分当金标,进 `eval_test`「测试库」。导入时带 ≥200 干扰文档。**简历上能量化的数字,以这套为准。**
2. **企业政策测试集**(`enterprise_policy_v1`,一键生成):自建 **12 篇中文制度 + 200 用例**,进 `enterprise_eval_test`「企业政策测试库」(跟 CRUD 分开)。定位是**贴企业场景的 sanity / 演示**——能讲「比 CRUD 更贴政策场景」,但**不是严格 benchmark**:
   - 全合成、作者手写,很多题是同一题换个问法(近重复),不算独立样本;
   - 只有 12 篇、没干扰文档,Hit@10 几乎必中(top-10 of 12);
   - 文档级匹配(找对那篇就行),不是段落级精度。
   - **所以量化主张仍以 CRUD 为准**,企业集只是「看跑得对不对 + 演示场景」。

### 报指标必须带策略和 N

**光说「Hit@5=0.9」没意义**——得说清「用哪种检索(Hybrid / BM25)、测了多少条(N)」。测 5 条全对和测 500 条全对差远了。所以每次报数:**策略 + N + 干扰设置** 一起说。

▸**面试可以说**:「主指标 Hit@1/5/10 + MRR,每次报必带检索策略和样本量 N。金标用 CRUD 的 questanswer,灌进专用测试库、带 200 干扰文档防虚高,业务库绝不灌金标。另有一套自建的企业政策测试集贴场景做演示,但它是小库合成无干扰的 sanity,量化主张仍以 CRUD 为准。」

---

## 数据与库约定（两套金标 + 隔离库）

**两套数据集，各进各的隔离评测库，业务库永不灌金标：**

1. **CRUD 金标**（主，量化简历指标用）：`questanswer_*` split；**不要**只用 `80000_docs` 当 QA；导入目标库 **code=`eval_test`，名「测试库」**；支持 ≥200 干扰文档，避免小库虚高。
2. **企业政策测试集**（新增，`enterprise_policy_v1`）：一键 `POST /api/eval/datasets/enterprise-seed`，自建 **12 篇中文制度 + 200 检索用例**，进 **code=`enterprise_eval_test`，名「企业政策测试库」**（与 eval_test 分开）。定位是**贴场景的 sanity / 演示**，不是严格 benchmark（边界见下）。
3. 两个评测库都在 `PROTECTED_EVALUATION_KB_CODES` 白名单；跑 Run 现在**必须先选「评测知识库」**，用例/金标限定在该库内，越界报 `EVAL_KB_SCOPE_INVALID`。
4. 索引在后台排队，导入接口不阻塞到按钮一直转圈。
5. 路径与更多约定见 `CLAUDE.md` / `docs/08`。

### 企业政策测试集：能讲什么、必须 caveat 什么

- **能讲**：比 CRUD 1-doc 整篇匹配更贴企业场景——12 篇主题相邻制度（请假 / 报销 / 采购 / 远程 / 安全 / 合规…）能制造真实词法混淆；200 用例带 difficulty / tags（direct / boundary / multi-step / exception / negative / cross-policy…），5 条是跨制度多金标。
- **必须 caveat**：① **全合成、作者手写**——24 条核心题 + 88 facts × 2 前缀模板扩写成 176 条，变体是近重复 query（同金标、仅前缀不同），**不是独立样本**；② **语料仅 12 篇、无干扰文档**，Hit@10 近乎必中（top-10 of 12），比 1-doc 可信但仍是小库；③ **文档级匹配**（`relevant_chunk_ids=[]`），不是 passage 精度；④ difficulty / tags 只存不聚合，**没有**按难度分层的 Hit@K。
- **结论口径**：企业测试集是**领域贴合的 sanity / demo**；**可量化的简历主张仍以 CRUD 金标为准**。

### 负样本：40 条「该拒答」的题（2026-08-28 新增）

**为什么要**：原来评测集里全是「该答上」的题，只能量「答得准不准」，量不出「该闭嘴的时候闭不闭嘴」。企业助手答错制度比答不出更贵，所以得专门测拒答。

**是什么**：企业套件里额外 seed 40 条**故意没有金标**的 query（语料里根本答不了），一半一半分两类：

| 类型 | 20 条例子 | 考什么 |
|---|---|---|
| `off_topic` | 「明天北京天气」「快排怎么写」「火锅底料配方」 | 底线题。完全不沾企业话术，拦不住说明门控坏了 |
| `near_miss` | 「婚假能休几天」「期权行权价怎么定」「手机通讯费能报吗」 | 难题。同样是企业话术、同样的问法，**但库里没这个主题** |

`near_miss` 是真靶子。这 20 条主题都 grep 确认过在 12 篇政策里出现 0 次，所以「拒答」是唯一正确答案。有两条是刻意的陷阱：语料里出现过一次「即时通讯工具」，所以「手机通讯费」能借到「通讯」这个词；「离职」在别的语境出现 5 次，所以它算 near_miss 不算 off_topic。

**指标怎么记（关键）**：负样本**绝不进 Hit@K / MRR**。没有金标，进去要么白送 0 分把指标做低、要么白送满分。它们走单独一条路，只记「拦住了没有」（`negative_gate.gate_blocked`），按 off_topic / near_miss 分开看。看板上 `N=` 只数正样本，负样本单独写 `neg=`——简历上的 `Hit@1（N=100）` 不会被 40 条负样本悄悄摊薄。

**顺带量出改进**：同一次 run 里，新门控和老门控（纯词面覆盖率）的结果都记下来，所以一次跑完能同时给出四个数——新门控误拦多少正样本、拦住多少负样本，老门控误拦多少、拦住多少。改进是量出来的，不是嘴上说的。门控本身怎么改的见 [09 诚实边界](../09-honesty-boundaries/README.md) 和 `docs/08` §12。

▸**面试可以说**：「我给评测集补了 40 条负样本，20 条完全跑题 + 20 条同话术但库里没有。负样本不进 Hit@K，它们只算拦截率，跟正样本的误拦率配对看，所以一次 run 能同时报出新旧门控的收益和代价。近似题（near_miss）是难点——比如问婚假，库里没有婚假制度，但『假』『员工』『申请』这些词到处都有，纯数词重叠很容易放过去。」

## 面试避坑

| 坑 | 正确说法 |
|---|---|
| 业务库灌金标 | 只用 eval_test |
| 只报 100% Hit@1 | 交代 N、干扰文档、是否 1-doc 任务 |
| 说 Hybrid 全面碾压 | 看曲线；无区分度就老实说接近 |
| 把 RAGAS 当主指标 | RAGAS 可选；主指标仍是 Hit@K/MRR |
| 把 memory salience 当检索分 | 两套分数，勿混淆 |
| 把企业测试集当严格 benchmark | 它是小库 / 合成 / 无干扰的 sanity；量化主张用 CRUD |
| 说选了 cross_encoder 一定有分 | 不可用会直接 503；无静默降级，数字对得上用的是哪种 rerank |
| 把负样本算进 Hit@K | 负样本没金标，只算 `negative_gate.gate_blocked`；`N=` 只数正样本 |
| 说分数门控在聊天里生效 | 默认聊天不开重排 → 没有 cross-encoder 分 → 走词面兜底；阈值 −8.0 也还是保守下界 |

## 演示路径（评估中心）

1. 选评测库并备数据：CRUD 导入 → `eval_test`（随机 50）；或一键 seed 企业政策测试集 → `enterprise_eval_test`  
2. 跑 Hybrid vs BM25  
3. 看板：Hit@1/5/10、MRR、策略、N  
4. Rerank 对比：同一 Run 选 `local_lexical_fusion` vs `cross_encoder`（真 NVIDIA）→ run summary 记 `reranker_method` / `reranker_backend`，数字说话；选 cross_encoder 不可用会直接报错、不静默降级  
5. 导出 JSON/CSV
