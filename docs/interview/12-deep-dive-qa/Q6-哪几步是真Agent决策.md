# Q6 · 六个环节里，哪几步真的是 Agent 在决策，哪几步就是固定 pipeline？

> 原话：「你简历里写这套是『multi-agent 中心化编排』，分诊、检索、Skill、Answer、合规发布、记忆回写六个环节。我想先确认：这六步里，哪几步是真的 Agent 在自己决策，哪几步其实就是一条固定 pipeline？」

**他在考什么**：你敢不敢自己拆穿「multi-agent」这个词。这是他的第一道诚实性测试。
**2026-08-25 实测**：答「只有分诊和 Answer 是真决策，其余是固定 pipeline」，他说「这个回答我认」。**这个答法是对的，保持。**

---

## 标准答法

> 六个环节里，**只有两个有真正的决策自由度**：分诊和 Answer。其余四个是固定 pipeline，位置和调用时机都是写死的。

| 环节 | 有没有决策自由度 | 决策什么 |
|---|---|---|
| **分诊 Router** | ✅ **有** | 选标签（三档）、选知识库、要不要改写 query、给几步计划 |
| 检索 | ❌ 没有 | 一个 Service，参数进去结果出来。**我特意没把它包装成 Agent** |
| Skill | ❌ 没有 | 触发条件是路由标签决定的，跑哪个规程是查表 |
| **Answer** | ✅ **有** | 调不调工具、调哪个、调几次、什么时候停下来写答案 |
| 合规发布 | ❌ 没有 | 固定的检查项逐条跑，出 warning code |
| 记忆回写 | ❌ 没有 | 固定阈值触发抽取，写不写由分数卡 |

---

## 想多拿分可以补的一句

复查环节（评审员 / 改写员）有点特殊，值得主动提：

> 复查里那个评审员是 LLM 在做判断（给 PASS 还是 NEEDS_IMPROVEMENT），**但它没有「选择动作」的自由**——什么时候跑、跑几轮、跑完交给谁，全是写死的。所以我算它是**「有判断、没决策」**，不算 Agent。

这句能显示你分得清「模型在里面做判断」和「Agent 在自己决策」——很多人混为一谈。

---

## 必说的边界

- ⚠️ **别用「multi-agent」这个词吹**。我这套是**中心化编排**：一个主流程按顺序调各环节，环节之间不互相对话、不协商。跟「多个 agent 平等协作」是两回事。
- ⚠️ **检索故意不做成 Agent**。它就是个 Service，包装成 Agent 只是为了凑数量，我没这么干。这点主动说是加分的。

---

## 别这么答

- ❌ 顺着「六个 agent」往下讲——他就是在等你自己拆穿。
- ❌ 说「都是 agent，各司其职」——直接归到「只讲框架不讲 tradeoff」。
