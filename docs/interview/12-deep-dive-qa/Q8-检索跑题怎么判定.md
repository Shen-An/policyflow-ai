# Q8 · 检索跑题怎么判定的？具体是什么信号触发重检？

> 原话：「你简历里写了『检索跑题自动重检一次』——那怎么判定跑题的？具体是什么信号触发重检？」
> 追问：「判定跑题的信号是『工具超时』，还是『用 LLM 判检索结果和 query 相关不相关』？到底是哪个触发的？」

**他在考什么**：简历上写的功能，你说不说得出**触发条件**。说不清等于这条是水的。

---

## 🚨 2026-08-25 实测：这题我答砸了

我当时说的是「**工具超时就认定它在错误方向调用**」+「**用 LLM 做一次检测**」——**两个都不对**，而且互相矛盾，所以他才追问「到底是哪个」。

**正确答案是第三个：本地词法重合率。**

---

## 标准答法（约 50 秒）

> **都不是。既不是超时，也不是 LLM 判断，是一个本地算的词法重合率。**
>
> 检索回来之后，我拿**用户的原始问题**和**证据（标题 + 片段）**各切一遍词，算重合率：
> **重合的词数 ÷ 问题的词数 < 0.08**，就判定这批证据跟问题对不上。（另外有个补充规则：命中了问题里的长英文词也算 supported，防止英文缩写被误杀。）
>
> **为什么用本地算的、不用 LLM 判**：这是每轮都要跑的关卡，用 LLM 判又慢又贵，而且每次结果还不一样。词法算法虽然糙，但**可复现、零成本、能解释**。
>
> **超时是另一回事**，跟跑题判定无关——那是预算保险丝（整轮 180 秒、单个工具 20 秒）。

---

## 三个触发码（他可能追「那具体判什么」）

`backend/app/rag/quality_gate.py:13`

| 码 | 什么时候出 |
|---|---|
| `NO_RELIABLE_EVIDENCE` | 一条证据都没查到 |
| `RETRIEVAL_LOW_QUALITY` | 有证据，但跟问题的词重合率 < 0.08 |
| `QUERY_REWRITE_DRIFT` | **query 被改写过**，而且改写后查出来的东西跟原问题对不上 |

出了任意一个 → 第一次就 `retry`，第二次还不行就 `refuse`（硬拒答，不硬编答案）。

---

## 重检具体做了什么（这才是关键，别只说「重查一次」）

**重检 = 用原始问题，把改写后的 query 换掉，再查一次。**（`pipeline.py:1013-1020`）

> 因为**怀疑对象是 query 改写**。多轮对话里短跟进句（比如「给我模板」）要靠改写补全主语，但改写有可能把话题带偏。所以第一反应是**退回用户原话再查一遍**。

**还有个不重试的分支，说出来是加分的**：

> 如果 query 压根没被改写过（改写后 == 原问题），我**不重试**。因为拿同一个 query 再查一次，结果必然一样，纯烧钱不产生新信号。这时候直接降级评估，该拒答就拒答。

---

## 必说的边界

- ⚠️ **0.08 这个阈值是拍的**，没做过调参实验。（这题的心法见 [[Q7-额度是拍的还是有数据]]）
- ⚠️ **纯词法，不理解语义**。用户问「年假」、文档写「带薪休假」，字面不重合就可能被误判成跑题。这是已知缺陷。
- ⚠️ **只重检一次**，不是无限重试。第二次还不行就硬拒答。

---

## 别这么答

- ❌ 「工具超时就说明方向错了」——超时是预算保险丝，跟相关性判定是两套东西，混起来说会被抓。
- ❌ 「用 LLM 判断相关性」——我没这么做，说了就是给自己挖坑，他会追「用什么 prompt、判得准不准」。
- ❌ 只说「重查一次」不说**换成原问题查**——那是这个设计的全部意义所在。
