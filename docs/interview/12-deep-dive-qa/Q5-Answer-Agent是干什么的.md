# Q5 · Answer Agent 到底干什么？是拿检索到的资料和 Skill 规则填答案吗？

> 我自己的疑问，不是面试官问的。但这是 [[Q3-谁来发现漏答]] 和 [[Q4-Answer-Agent的决策空间]] 的基本盘，讲不清前面全白搭。

---

## 一句话答案

**它是「写稿的人」，不是「填表的机器」。**

> Answer Agent 是**唯一真正动笔写字的那个环节**。
> 前面所有环节（分诊、检索、Skill）都是给它备料，
> 后面所有环节（复查、合规检查）都是审它写的东西。
> 而且它自己也能在写的过程中回头取料。

---

## 它拿到的材料（全都塞进提示词）

| 材料 | 是什么 |
|---|---|
| 用户问题 | 原问题 |
| **证据** | 检索到的制度原文片段，带编号 `[1] [2] [3]` |
| **Skill 结果** | 上游已经算好的结构化清单 / 对比表 / 摘要 |
| 记忆 | 历史对话 + 用户偏好 |
| 计划 | 多步任务时的步骤清单 |

---

## 「拿资料填答案」这个理解要修三处

### ① 不是「填」，是「写」

没有模板槽位。这些材料是拼成一大段文字丢给大模型，让它**自己生成**整段回答。约束全靠提示词里的规矩，**不是靠代码保证**。

这点很重要——**正因为是生成，所以它会犯错**，这就是为什么后面还得有复查（见 [[Q3-谁来发现漏答]]）。如果是模板填空，就不需要复查了。

### ② Skill 给的不是「规则」，是**已经算好的结果**

不是「Skill 提供一套规则，Answer Agent 照着执行」。
是 Skill 已经把证据整理成结构化的清单 / 对比了，Answer Agent 的活是**把这个结构翻译成人话**。

提示词里专门写了一条（`answer_agent.py:67`）：

> 若上游 Skill 已产出清单/对比/摘要结构化结果，应优先将其整理为可读回答，并继续用 [1]、[2] 标注制度证据；**不要丢弃 Skill 中的步骤/维度**。

最后那句是防止模型「自由发挥把 Skill 算好的步骤简化掉」。

### ③ 它不是纯被动的

手上有 6 个工具，写到一半发现材料不够可以自己再去取。
额度细节见 [[Q4-Answer-Agent的决策空间]]（**补查实际只有 1 次**）。

## 还有一个职责：没证据时怎么办

这是个分叉（`answer_agent.py:110`）：

| 开关 | 行为 |
|---|---|
| **默认**（`CHAT_HARD_REFUSE_WITHOUT_EVIDENCE=True`） | 直接返回固定拒答话术，**连模型都不调**。没证据就不生成，从源头掐掉编造 |
| 关掉时 | 可以让模型凭通用知识答，但强制在开头贴一大段「未检索到依据 · 模型参考回答 · **不可信** · 需你自行判断」，并且自信分**直接记 0** |

这条是 [诚实边界](../09-honesty-boundaries/README.md) 里最硬的一条，面试时值得主动讲。

---

## 提示词里的四条硬规矩（这是它的「性格」）

1. 只能依据证据答制度事实，**不得补充证据里没有的硬性数值**
2. 记忆和历史对话**只能用来理解指代和调整语气，绝不能覆盖制度证据**
3. 计划只是流程指引，**不能替代证据，不能编造还没执行的步骤的结果**
4. 用户要模板 / 表单时：**不许因为证据里没有「模板」两个字就拒答**，要基于制度要求整理出可填写的字段结构，但必须标注「非正式系统表单」

> 第 4 条是踩坑加的——之前用户问「给我个报销模板」，模型看证据里没「模板」二字就说没有，很蠢。

---

## 最后它给自己打个分

生成完顺手算一个自信分（算法见 [[Q3-谁来发现漏答]]）。有两处保守封顶：

| 情况 | 封顶 |
|---|---|
| 问题里有「模板 / 表单 / 怎么填」 | 0.85（这类答案是合成的，不该太自信） |
| 用过工具 | 0.9 |

这个分是**临时的**，后面 pipeline 拿到合规检查结果还会重算一遍。
