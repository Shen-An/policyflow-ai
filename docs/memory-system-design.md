# PolicyFlow AI · 记忆系统设计说明

> 面向多轮对话的四层记忆:短期窗口 + 滚动摘要 + 事件级长期记忆 + 实体/偏好感知。
> 设计原则:**记忆服务于「理解上下文」,绝不作为制度权威**——任何一轮回答仍以当轮 RAG 检索到的制度证据为准。

---

## 1. 为什么要分层

多轮对话不能把全部历史原样塞进上下文:token 会爆,且旧内容会干扰当前问题。
所以做**分层管理**——不同「新鲜度 / 重要度」的信息,用不同的方式存储和召回,拼提示词时各取所需。

一条核心约束贯穿始终:**记忆非权威(non-authoritative)**。它只用来解决指代(「他 / 那份 / 上次说的」)和沿用用户风格偏好,**不能覆盖当轮检索到的制度条款**;制度事实也**禁止**被当成「偏好」写进记忆。

---

## 2. 四层记忆结构

| 层             | 存储位置                                | 存什么                       | 角色                       |
| ------------- | ----------------------------------- | ------------------------- | ------------------------ |
| **L0 原始层**    | `messages` 表                        | 全量原始对话,逐条保留               | 事实底座,永不因压缩被物理删除          |
| **L1 短期层**    | 最近 K 轮 + `conversations.summary`    | 最近几轮原话 + 一段滚动摘要           | 短期工作记忆(热) + 早期对话的压缩提要(温) |
| **L2 长期事件层**  | `memory_items`(long_term_event)     | 值得长期记住的「事件」(决定 / 待办 / 事实) | 按相关性召回的长期记忆(冷)           |
| **L3 实体/偏好层** | `memory_items`(entity / preference) | 用户是谁、在哪个部门、喜欢什么风格         | 长期稳定的画像,常驻装配             |

打个比方:L0 是全程录音;L1 是桌上摊开的几张纸 + 一张便签摘要;L2 是能翻能搜的工作笔记;L3 是名片夹 + 习惯小本。

---

## 3. 短期记忆(STM)

- **滑动窗口**:装配提示词时取**最近 6 轮**原话(`MEMORY_STM_WINDOW_TURNS=6`),原样放入,保证短期连贯。
- **滚动摘要**:对话累积到阈值(`MEMORY_COMPRESS_TURN_THRESHOLD=8`)后,把滑出窗口的早期对话压缩成一段摘要,写入 `conversations.summary`,后续持续滚动更新。
- **不物理删除**:被压缩、滑出窗口的原话**仍完整保留在 L0**,只是这一轮没有放进提示词而已。

> 效果:上下文长度可控,但「早先聊过什么」不丢——用一段摘要顶替一大段原文。

---

## 4. 长期记忆(LTM)· 事件级

### 4.1 怎么写入(异步抽取 + 显著性门槛)

每轮对话结束后,从这一轮里抽取「值得长期记住的事件」(`extract_memory_events`):

- **主用 LLM 结构化抽取**:让模型只输出 JSON 数组,每条一个粒度,字段包括 `event_type` / `summary` / `entities` / `salience` / `policy_related` / `facts`。事件类型限定为 `preference | decision | todo | entity_update | conversation_fact`。
- **规则兜底**:LLM 不可用时,用正则启发式抽取(识别偏好句式、部门/角色实体、实质性问答),保证不崩。
- **显著性门槛**:只有 `salience ≥ 0.55`(`MEMORY_LTM_SALIENCE_THRESHOLD`)的事件才写入长期记忆,过滤寒暄和低价值内容。

抽取时明确要求模型:**不要把制度条款正文写进 preference**、寒暄返回空、制度问答本身标 `policy_related=true`——从写入源头守住「记忆非权威」。

### 4.2 怎么召回(相关性为主的融合排序,取 top-5)

召回时对候选记忆打一个综合分,排序后**只取前 5 条**(`MEMORY_LTM_TOP_K=5`)放入提示词:

```text
relevance    = max(vector_sim, keyword * 0.85)      # 向量相似度与关键词匹配取较高者
importance   = 0.5 * confidence + 0.5 * salience    # 写入时的置信度与显著性
recency      = exp(-λ * age_days)                   # 时间衰减,λ 默认 0.08
access_boost = min(0.15, log1p(access_count) * 0.03)# 常被用到的记忆小幅加分,封顶

final = relevance * (0.55 + 0.35 * importance + 0.10 * recency) + access_boost
```

一句话:**先看相不相关(大头),再看重不重要,新旧只占一小成,常用的加一点点**。
向量存在 `memory_items.embedding` 字段,召回时用余弦相似度比对(当前用户、未过期的条目范围内),不是独立向量数据库。

## 5. 实体感知(Entity Perception)

系统会主动识别并累积「用户是谁 / 关心什么」:

- **抽取**:从对话里识别实体(如「我的部门是财务部」「我负责采购」),LLM 抽取为主、正则兜底,标注类型(department / person_or_role / …)。
- **去重合并(upsert)**:以 `类型:名称` 作为实体键(`upsert_entity`)。同一实体再次出现时**不新建、而是合并 facts**(去重、保留最近 20 条),并刷新摘要——所以「财务部」不会被记成好几条,而是一条持续长胖的画像。
- **常驻装配**:实体和固定偏好在拼提示词时**直接常驻**(实体上限 8 条、偏好上限 10 条),**不走时间衰减召回**——避免「用户在财务部」这种长期事实因为久没提到就被 recency 压没。

> 面试点:实体层解决的是「跨轮的身份/关注点连续性」,和 L2 事件的「按需相关召回」是两种不同的记忆使用方式。

---

## 6. 冷 / 热 / 温:是装配策略,不是三个仓库

「冷热」指的是**拼提示词时把记忆摆在哪**,底层不存在独立的冷热存储:

| 区 | 内容 | 来源 |
|---|---|---|
| **热(hot)** | 最近 6 轮原话 | STM 窗口 |
| **温(warm)** | 滚动摘要 + 固定偏好 / 实体 | summary + 常驻画像 |
| **冷(cold→selected)** | 按当前问题排序后选出的 top-5 长期事件 | LTM 排序截断 |

窗外的原始对话仍在 L0,没有被删除。

---

## 7. 生命周期与 TTL

- **低显著性对话事实**:默认 TTL 30 天(`MEMORY_CONVERSATION_FACT_TTL_DAYS`),到期清理。
- **短期卸载事件**:更短 TTL 14 天(`MEMORY_STM_UNLOAD_TTL_DAYS`)。
- **偏好 / 实体**:长期有效,不设过期。
- **管理面**:`GET / DELETE /api/memory`,**仅本人可见可删**;前端有「我的记忆」页面,记忆完全可查、可删,不是黑盒。

---

## 8. 诚实边界(重要)

| 约束 | 说明 |
|---|---|
| **记忆非权威** | 只服务指代与风格,**不能覆盖当轮 RAG 检索到的制度证据**。 |
| **偏好禁写制度事实** | 不会把「年假 5 天」这类条款当偏好存(`MEMORY_POLICY_FACT_FORBIDDEN`);制度以检索为准。 |
| **短跟进靠 query rewrite** | 「给我模板」这种省略句,先结合历史改写检索 query,不只靠窗口硬翻。 |
| **向量存储轻量** | embedding 存在 SQLite 字段、余弦相似度全量比对;演示/单用户量级足够,大规模需换 ANN 索引。 |
| **抽取可能有噪声** | LLM 抽取非 100% 准确,故设显著性门槛 + TTL + 用户可删三重兜底。 |

---

## 9. 关键参数一览

| 参数 | 默认值 | 含义 |
|---|---|---|
| `MEMORY_STM_WINDOW_TURNS` | 6 | 短期窗口保留最近轮数 |
| `MEMORY_COMPRESS_TURN_THRESHOLD` | 8 | 触发滚动摘要压缩的轮数 |
| `MEMORY_LTM_TOP_K` | 5 | 长期事件召回条数 |
| `MEMORY_LTM_SALIENCE_THRESHOLD` | 0.55 | 事件写入长期记忆的显著性门槛 |
| `MEMORY_FIXED_PREFS_LIMIT` | 10 | 常驻偏好上限 |
| `MEMORY_ENTITY_LIMIT` | 8 | 常驻实体上限 |
| `MEMORY_RANK_DECAY_LAMBDA` | 0.08 | 时间衰减系数 λ |
| `MEMORY_RANK_ACCESS_BOOST_CAP` | 0.15 | 访问热度加分上限 |
| `MEMORY_CONVERSATION_FACT_TTL_DAYS` | 30 | 低显著性对话事实存活天数 |
| `MEMORY_STM_UNLOAD_TTL_DAYS` | 14 | 短期卸载事件存活天数 |

### 一分钟口述版

> 多轮对话我做了四层记忆:L0 全量原话永久留底;L1 最近 6 轮原话 + 一段滚动摘要;L2 是从每轮里抽取、显著性达标才写入的长期事件,召回时按「相关性 × 重要性 × 时间衰减」排序取 top-5;L3 是实体和偏好画像,靠 upsert 去重合并、常驻装配不走衰减。冷热是拼提示词的摆放策略,不是三套存储。最关键的一条:**记忆非权威,只服务指代和风格,任何制度结论仍以当轮检索证据为准**,而且制度条款禁止被当偏好存,用户还能随时查看和删除自己的记忆。
