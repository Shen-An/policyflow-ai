## 本轮未运行 / 未满足的关键条件

1. **分布式 Locust（T156）**：没有独立压测环境；本机单进程即使跑出数字也不能代表验收环境，因此不产出任何 p95/RPS 结论。
2. **PostgreSQL 迁移对照（T149 的 PG 部分）**：实例未启动，PG 套件 skip；只有便携审计（counts/FK/unique/hash）在 SQLite 上真跑。
3. **Electron E2E（T155 的桌面部分）**：R40 的复跑结果是**失败**——`artifacts/acceptance/desktop/electron-e2e.txt` + `electron-e2e-exit.txt` 记录 **8 spec 全失败、0 passed / 8 failed、exit=1**，根因是 WDIO 建会话失败（`session not created: DevToolsActivePort file doesn't exist`，`electron.exe` 已退出）。该日志只证明“启动失败”，不能据此断定唯一原因是没有桌面会话。本轮 vitest 为 47 文件 / 155 passed。
4. **release window 零使用（T158）**：窗口 2026-10-18 → 2026-11-18 尚未结束；`artifacts/acceptance/legacy-exit.json` 显示 `eligible_for_removal=false`，且 browser shell / facade 两个面**未测量**。因此 T159/T160 的删除**没有执行**。
5. **验收压测的代码前置条件**：分流、逐帧 SSE 计时、实际并发采集、tenant 分散登录与跨租户断言均已实现并有单测（`tests/load/test_acceptance_profile.py`），但**验收环境运行本身未做**，所以 SC-001–SC-005 仍然没有通过证据。
